# Blender and asset scope

Read this for Blender, GLB, asset, material or bespoke-showcase work. Read `EXPORT_CONTRACT.md` for Studio template metadata, and the matching showcase README for a bespoke room. Source-folder briefs record the original inputs; open only the selected showcase's brief, and use its parent showcase README for current build, export and runtime status.

- Keep Studio templates separate from bespoke showcases. Do not introduce Studio metadata, publication behavior or asset contracts into a read-only showcase.
- Preserve legacy `aura_*` extras, node names, colliders, navigation and surface IDs. Keep authoring units/axes and color-space rules explicit.
- Retain primary `.blend` files, licensed/original assets and final approved masters. Add provenance to `ASSET_LICENSES.md`; keep scratch renders, caches and backups ignored.
- Verify exports with the relevant GLB/asset report and review Arrange, Walk, Overview, reduced motion and 1440 × 1000 plus 390 × 844 output after visual changes.
- Do not reduce material/geometry quality merely to satisfy a benchmark; measure and document deliberate delivery tradeoffs.
